# bsp-dev-c

RoboMaster 开发板 C 型的 LibXR / XRobot BSP / LibXR and XRobot BSP for the RoboMaster Development Board Type C

## 1. 板子与平台 / Board and Platform

开发板为 RoboMaster 开发板 C 型，主控 STM32F407IGHx（Cortex-M4F），运行 FreeRTOS，外设驱动来自 LibXR。工程由 CubeMX 工程 `DevC.ioc` 生成，LibXR 以子模块形式位于 `Middlewares/Third_Party/LibXR`。`User/app_main.cpp` 由 CodeGenerator 生成，创建 CAN、UART、SPI、I2C、PWM、ADC、GPIO、USB 等外设对象，通过 `XR_REGISTER` 注册硬件，并调用 `XROBOT_MAIN()`；配置中的硬件名即这里注册的对象名，例如 `can1`、`usart3`、`spi1`、`LED_B`。终端使用 USB OTG FS 的 CDC 串口（`usb_otg_fs_cdc`），USB OTG HS 提供两路 CDC 串口（`usb_otg_hs_cdc`、`usb_otg_hs_cdc2`）。

FreeRTOS 堆 `ucHeap`（64 KiB）位于 CCM RAM 的 `.ccm_heap` 段，链接脚本 `STM32F407xx_FLASH.ld` 将该段标为 `NOLOAD`，Flash 中不保存其初始化镜像。

| 路径 | 内容 |
| --- | --- |
| `DevC.ioc` | CubeMX 工程 |
| `Core/`、`Drivers/`、`Middlewares/` | CubeMX 生成的初始化代码、ST HAL / CMSIS、FreeRTOS、ST USB Device 库、LibXR 子模块 |
| `User/app_main.cpp` | 入口源文件，注册硬件并调用 `XROBOT_MAIN()` |
| `User/libxr_config.yaml` | LibXR 外设参数，`generator:` 记录 CodeGenerator 版本 |
| `User/xrobot.yaml`、`User/RobotConfig/*.yaml` | 配置 |
| `Modules/modules.yaml`、`Modules/sources.yaml` | 需要的模块（`xrobot:` 记录 XRobot 版本）与模块源 |
| `xrobot.lock` | 每个模块使用的提交 |
| `tools/` | 构建、格式化与调试脚本 |

`Modules/<owner>/<Repo>/`、`Modules/CMakeLists.txt` 和 `User/xrobot_main.hpp` 由 `xrobot` 生成，不提交到仓库。

The board is the RoboMaster Development Board Type C with an STM32F407IGHx (Cortex-M4F) running FreeRTOS; peripheral drivers come from LibXR. The project is generated from the CubeMX project `DevC.ioc`, and LibXR is a submodule at `Middlewares/Third_Party/LibXR`. `User/app_main.cpp` is generated by the CodeGenerator: it creates the CAN, UART, SPI, I2C, PWM, ADC, GPIO and USB objects, registers them with `XR_REGISTER` and calls `XROBOT_MAIN()`. Hardware names in a configuration are the object names registered there, for example `can1`, `usart3`, `spi1` and `LED_B`. The terminal uses the CDC serial port of USB OTG FS (`usb_otg_fs_cdc`); USB OTG HS provides two CDC serial ports (`usb_otg_hs_cdc`, `usb_otg_hs_cdc2`).

The FreeRTOS heap `ucHeap` (64 KiB) is placed in the `.ccm_heap` section of CCM RAM. The linker script `STM32F407xx_FLASH.ld` marks the section `NOLOAD`, so Flash holds no initialization image for it.

| Path | Content |
| --- | --- |
| `DevC.ioc` | CubeMX project |
| `Core/`, `Drivers/`, `Middlewares/` | CubeMX-generated initialization code, ST HAL / CMSIS, FreeRTOS, ST USB Device library, LibXR submodule |
| `User/app_main.cpp` | Entry source: registers the hardware and calls `XROBOT_MAIN()` |
| `User/libxr_config.yaml` | LibXR peripheral parameters; `generator:` records the CodeGenerator version |
| `User/xrobot.yaml`, `User/RobotConfig/*.yaml` | Configurations |
| `Modules/modules.yaml`, `Modules/sources.yaml` | Required Modules (`xrobot:` records the XRobot version) and Module sources |
| `xrobot.lock` | The commit used for each Module |
| `tools/` | Build, formatting and debug scripts |

`Modules/<owner>/<Repo>/`, `Modules/CMakeLists.txt` and `User/xrobot_main.hpp` are generated by `xrobot` and are not committed to the repository.

## 3. 构建 / Build

构建需要 Python（用于 `xrobot` 与 `libxr`）、CMake、Ninja 和 ST 的 `starm-clang` 工具链（STM32CubeCLT 或 VS Code STM32Cube 扩展提供），`starm-clang` 位于 `PATH` 中。预设使用 `cmake/starm-clang.cmake`；`-DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake` 改用 `arm-none-eabi-gcc`。环境变量 `GCC_TOOLCHAIN_ROOT` 和 `CLANG_GCC_CMSIS_COMPILER` 在把 `STARM_TOOLCHAIN_CONFIG` 设为 `STARM_HYBRID` 时使用。

```bash
$ git clone --recursive https://github.com/QDU-Robomaster/bsp-dev-c.git
$ cd bsp-dev-c
$ pip install xrobot==1.0.0 libxr==6.0.0
$ xrobot setup
$ xrobot gen -c User/RobotConfig/hero.yaml
$ cmake --preset debug
$ cmake --build --preset debug
```

`xrobot` 与 `libxr` 的版本由 `Modules/modules.yaml` 的 `xrobot:` 和 `User/libxr_config.yaml` 的 `generator:` 记录。`xrobot setup` 按 lock 拉取模块、检查所有配置并生成 `User/xrobot_main.hpp`；`xrobot gen -c <配置>` 选择要构建的配置，省略时使用 `User/xrobot.yaml`。已克隆的仓库先运行 `git submodule update --init --recursive`。

CMake 预设有 `debug`、`relWithDebInfo`、`release` 和 `minSizeRel`，输出位于 `build/<预设>/DevC.elf`。构建前，LibXR 检查配置、lock、模块头文件和入口源文件中的注册是否与已生成的 `User/xrobot_main.hpp` 一致；不一致时构建失败，并提示对应的 `xrobot gen -c <配置>`。`tools/build.sh -c <配置> -p <预设>` 依次执行格式化、`xrobot gen`、`cube-cmake` 配置与构建。

修改 CubeMX 配置并重新生成代码后，由 CodeGenerator 重新生成 BSP 对象：

```bash
$ libxr parse -d . -o .config.yaml
$ libxr gen -i .config.yaml -o User/app_main.cpp --xrobot --libxr-config User/libxr_config.yaml
```

`User/app_main.cpp`、`User/app_main.h`、`User/flash_map.hpp` 和 `User/libxr_config.yaml` 提交到仓库，`User Code` 区域的内容保留。命令的完整说明见 [LibXR CodeGenerator](https://github.com/xrobot-org/LibXR_CppCodeGenerator)。

持续集成见 `.github/workflows/xrobot_stm32.yml`：在 `ghcr.io/xrobot-org/docker-image-stm32:main` 中安装固定版本的工具，重新生成并检查 BSP 对象，运行 `xrobot format --check` 和 `xrobot setup --frozen`，再为默认配置和每份 `User/RobotConfig/*.yaml` 构建 Release 固件。发布 Release 或推送 `v*` 标签时，各配置的 `.elf`、`.hex`、`.bin` 随之上传。分支 `dev` 接收修改，`master` 通过来自 `dev` 的 PR 更新。

Building needs Python (for `xrobot` and `libxr`), CMake, Ninja and ST's `starm-clang` toolchain (provided by STM32CubeCLT or the VS Code STM32Cube extension) on `PATH`. The presets use `cmake/starm-clang.cmake`; `-DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake` selects `arm-none-eabi-gcc` instead. The environment variables `GCC_TOOLCHAIN_ROOT` and `CLANG_GCC_CMSIS_COMPILER` apply when `STARM_TOOLCHAIN_CONFIG` is set to `STARM_HYBRID`.

The versions of `xrobot` and `libxr` are recorded in `xrobot:` of `Modules/modules.yaml` and `generator:` of `User/libxr_config.yaml`. `xrobot setup` fetches the Modules at the commits in the lock, checks every configuration and generates `User/xrobot_main.hpp`; `xrobot gen -c <configuration>` selects the configuration to build and defaults to `User/xrobot.yaml`. A repository that is already cloned first runs `git submodule update --init --recursive`.

The CMake presets are `debug`, `relWithDebInfo`, `release` and `minSizeRel`; the output is `build/<preset>/DevC.elf`. Before building, LibXR checks that the configuration, lock, Module headers and the registrations in the entry source match the generated `User/xrobot_main.hpp`; on a mismatch the build fails and names the `xrobot gen -c <configuration>` command to run. `tools/build.sh -c <configuration> -p <preset>` runs formatting, `xrobot gen`, and the `cube-cmake` configure and build steps in turn.

After changing the CubeMX configuration and regenerating its code, the CodeGenerator regenerates the BSP objects with the two `libxr` commands shown above. `User/app_main.cpp`, `User/app_main.h`, `User/flash_map.hpp` and `User/libxr_config.yaml` are committed, and the content of the `User Code` regions is preserved. The commands are documented in the [LibXR CodeGenerator](https://github.com/xrobot-org/LibXR_CppCodeGenerator) repository.

Continuous integration is defined in `.github/workflows/xrobot_stm32.yml`: in `ghcr.io/xrobot-org/docker-image-stm32:main` it installs the pinned tools, regenerates and checks the BSP objects, runs `xrobot format --check` and `xrobot setup --frozen`, and builds Release firmware for the default configuration and every `User/RobotConfig/*.yaml`. Publishing a Release or pushing a `v*` tag uploads the `.elf`, `.hex` and `.bin` of each configuration. The branch `dev` receives changes, and `master` is updated through PRs from `dev`.

## 4. 烧录与运行 / Flash and Run

`DevC.jdebug` 是 SEGGER Ozone 工程：设备 STM32F407IG，SWD 接口，速率 4 MHz，加载 `build/debug/DevC.elf` 并启用 FreeRTOS 插件。使用 CMSIS-DAP（DAPLink）调试器时，`tools/ozone_openocd_launcher.sh` 启动 OpenOCD（`interface/cmsis-dap.cfg`、`target/stm32f4x.cfg`、SWD），GDB 服务位于 `127.0.0.1:3333`：

```bash
$ ./tools/ozone_openocd_launcher.sh --openocd-path <OpenOCD 目录>
```

`.vscode/launch.json` 提供 ST-Link 与 J-Link 的 GDB 调试配置。CI 与 Release 发布的 `.hex` / `.bin` 也可用任意 SWD 烧录工具写入。运行后，终端可通过 USB CDC 串口访问。

`DevC.jdebug` is a SEGGER Ozone project: device STM32F407IG, SWD interface at 4 MHz, loading `build/debug/DevC.elf` with the FreeRTOS plugin. With a CMSIS-DAP (DAPLink) probe, `tools/ozone_openocd_launcher.sh` starts OpenOCD (`interface/cmsis-dap.cfg`, `target/stm32f4x.cfg`, SWD) and serves GDB at `127.0.0.1:3333`, as in the command above.

`.vscode/launch.json` provides GDB debug configurations for ST-Link and J-Link. The `.hex` and `.bin` files from CI and from Releases can also be written with any SWD programming tool. After start-up, the terminal is available on the USB CDC serial port.
